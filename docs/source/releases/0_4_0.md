# 0.4.0 release notes

This pre-1.0 release corrects EXIF tag identity, directory selection, and
write validation. It includes breaking changes; read the
[0.4.0 migration guide](../user_guide/migration_0_4_0.md) before upgrading.

- Ambiguous names and IDs require an explicit IFD. Shared definitions can
  still use a configured default directory.
- `ExifImage.tag_entries` preserves occurrences by `(ifd, tag_id)`. CLI and
  dictionary output preserve repeated names with IFD-qualified keys.
- Low-level writes validate known type, range, shape, and count constraints
  before mutation. Errors identify the actual target directory.
- The tested tag baseline has count metadata, including Orientation and
  the EXIF three-component BitsPerSample definition. Entries outside that
  baseline can still have unspecified counts; those counts are not checked.
- The piexif backend preserves existing embedded JPEG thumbnails and IFD1
  metadata. Saving IFD1 tags without a thumbnail payload fails before the
  file is changed.

The GPS convenience API remains planned separately. The migration guide
describes available helpers, value representations, and persistence limits.
